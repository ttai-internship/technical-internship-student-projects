# B03：小型 Web 功能切片

## 定位

- 等级：初级
- 推荐周期：一周；一月可完成多个小切片
- 适合：已经能运行基础 Web 项目，希望了解系统结构和协作流程的学生
- 主线：需求切片 + 简单系统设计 + Git/PR/CI

## 入场与降难度规则

- 如果第一天诊断低于 8 分，先完成 [B00 基础起步门](../../foundation/README.md)；完全零基础不从 HTTP 概念开始。
- 一周只选择一个切片，建议先做 `status` 筛选；先直接调用 `filter_tickets`，再观察 `encode_tickets`，最后才运行 HTTP 服务。
- 不要求前端框架、数据库、部署或异步编程；这些内容只能作为 Stretch。
- 导师只需要给出一张“请求 → 函数 → JSON”流程图和一个边界用例，避免学生在服务器配置上耗时。

## 背景

starter repository 是一个已经可以运行的任务或工单管理 Demo。学生只修改指定功能，不从零搭建完整网站。

## Starter code

```text
backend/
├── routes/tickets.py
├── services/ticket_service.py
└── tests/
frontend/
├── pages/tickets.html
└── components/filter.js
.github/workflows/ci.yml
```

每位学生从以下三个切片中选择一个：

- 增加状态筛选；
- 增加表单校验；
- 增加空数据和错误状态提示。

## 学生完成的核心代码

- 一个指定接口或前端组件；
- 一个输入校验或状态处理分支；
- 至少两个测试用例；
- 一张请求流程图或模块关系图。

## Core 验收

1. 正常场景得到预期结果；
2. 空输入、非法输入或空数据有明确处理；
3. 原有功能不回归；
4. 本地测试和 CI 通过；
5. PR 描述包含背景、修改范围和验证结果；
6. 学生可以说明请求从入口到结果经过哪些模块。

## 必交材料

- 代码；
- 测试结果；
- 结构图；
- PR 链接；
- 一段“我遇到的第一个错误以及如何定位”的记录。

## Stretch

- 增加分页或排序；
- 增加一个新的测试场景；
- 改善错误提示，但不改变原有接口约定。

## 周期扩展

- 一周：完成一个功能切片；
- 一月：完成两个切片并进行一次小型重构；
- 两月以上：可转为中级工程项目，不再使用本卡作为唯一任务。
