# A02：RAG/Agent 评估系统

## 定位

- 等级：高级
- 推荐周期：一月或两月；一周只完成评估切片
- 适合：已经能够构建基本 LLM 应用，希望研究“系统是否真的变好”的学生
- 主线：固定数据集 + baseline + 评估指标 + 失败分析

## 背景

项目重点不是再做一个 Demo，而是为一个受限的 RAG 或 Agent 系统建立可以重复运行的评估流程。

## Starter code

```text
ingest.py
retriever.py
generator.py
evaluate.py
metrics.py
eval/
├── documents/
├── questions.json
└── expected.json
reports/
```

项目提供脱敏文档、问题集、baseline 输出和基础评估脚本。

## 学生完成的核心代码

- 改进文档切分、检索、Prompt 或重排序中的一个环节；
- 增加至少一个评估指标；
- 运行改动前后的对比；
- 对错误进行分类；
- 写出不能由当前实验证明的结论。

## Core 验收

1. 所有实验使用同一份固定问题集；
2. 有明确 baseline；
3. 改动前后结果可以复现；
4. 至少区分检索错误、生成错误和问题理解错误；
5. 报告包含成功率、失败案例和指标局限；
6. 不能只展示几个成功回答作为结论。

## 必交材料

- 评估脚本；
- 数据集版本和问题集；
- baseline/改进结果；
- 失败案例分类表；
- 评估报告。

## Stretch

- 增加回归测试；
- 增加人工评估表；
- 记录延迟和成本；
- 增加一个新的检索策略。

## 周期扩展

- 一周：完成一组固定案例和一个指标；
- 一月：完成完整评估流程和错误分类；
- 两月：比较多个策略并形成工程建议；
- 半年：围绕 Agent 评估、可靠性或成本形成研究课题。
